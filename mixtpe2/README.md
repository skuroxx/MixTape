# MixTape

- `client/`  readable browser source (app.js, style.css, amlyrics.*). Edit these. They are never served.
- `public/`  generated by `scripts/build-client.mjs` (minified + mangled). Don't edit; rebuilt by `npm run dev` / `npm run build`.
- `app/api`, `lib/`  server code (runs on the server, never sent to the browser).
- `dev-demo/`  lyrics demo page, not deployed.

    npm install
    npm run dev      # rebuilds client assets, then starts Next
    npm run build    # production build (also strips console.* from the client bundle)

## Streaming audio through a Cloudflare Worker

`worker/` is a Cloudflare Worker that resolves a YouTube audio stream and proxies the bytes (seeking works).
It resolves with `@distube/ytdl-core` (`new Ytdl().getInfo(id)`, the same call as the original snippet), pinned to the `visionos`
client because that is the one that needs no player script (Workers can't run the `vm`/`eval` solver the other clients use).
`wrangler.toml` defines `import.meta.url` and enables `nodejs_compat` so the library can load. If ytdl-core fails, the Worker
falls back to asking YouTube's player endpoint directly (android_vr, then android).
Your Vercel `/api/extract` calls it, so playback no longer depends on Vercel's IP. If the Worker isn't set up or is
down, `/api/extract` falls back to the old local `@distube/ytdl-core` path, and the player falls back to the YouTube player.

Deploy (once):

    cd worker
    npx wrangler login
    npx wrangler secret put STREAM_SECRET        # any long random string
    npx wrangler deploy                          # prints https://mixtape-stream.<you>.workers.dev
    # in wrangler.toml set ALLOWED_ORIGINS to your site, e.g. "https://mixtape.vercel.app" (comma-separated)

In Vercel -> Project -> Settings -> Environment Variables:

    STREAM_WORKER_URL = https://mixtape-stream.<you>.workers.dev
    STREAM_SECRET     = (the same value you gave wrangler)


### Setting the Worker up from the Cloudflare website (no terminal)

**A. From GitHub (recommended, handles everything automatically)**
1. Push this project to GitHub.
2. Cloudflare dashboard -> Workers & Pages -> Create application -> connect to Git -> pick the repo.
3. Project/Worker name: `mixtape-stream` (must match `name` in `worker/wrangler.toml`).
4. **Root directory: `worker`**. Build command: leave empty. Deploy command: `npx wrangler deploy` (default). Save and Deploy.
5. Worker -> Settings -> Variables and Secrets -> add a **Secret** named `STREAM_SECRET` (long random string).

**B. Paste one file (no GitHub)**
1. Workers & Pages -> Create application -> "Start with Hello World" -> name it `mixtape-stream` -> Deploy -> Edit code.
2. Delete the sample code, paste the whole of `mixtape-stream-worker.js`, Deploy.
3. Settings -> Runtime -> Compatibility flags -> add `nodejs_compat`.
4. Settings -> Variables and Secrets -> add a **Secret** `STREAM_SECRET`.

Then in the app: Settings -> **Audio source -> Direct stream**. While audio plays through the stream, an **OPUS** tag
(or AAC) shows beside the artist name. With the YouTube player source there is no tag.

Checks:

    npm run test:worker                                   # offline unit tests (mocked YouTube)
    STREAM_WORKER_URL=... STREAM_SECRET=... npm run test:stream -- "Get Lucky Daft Punk"   # live: search -> resolve -> fetch bytes
